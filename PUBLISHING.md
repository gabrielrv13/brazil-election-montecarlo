# Publishing a forecast

Checklist for posting a runoff forecast. The same discipline applies to first-round posts made with `python -m src run`.

## 1. Final run

```bash
python -m src runoff --as-of YYYY-MM-DD --seed 42
```

- Use only polls published up to `--as-of`. The runoff keeps only polls after the first round by default; `--data-min` overrides it.
- The run writes `outputs/resumo_2turno.json`, `outputs/resultados_2turno_standalone.csv`, `outputs/simulacao_2turno.png` and `outputs/resumo_2turno.manifest.json`. The manifest records the commit, seed, parameters and the SHA-256 of the input CSV and of every output.
- Commit the poll CSV first, so the manifest's commit and input hash identify the data.

## 2. Publication gate

```bash
python src/publicar_2turno.py --exigir-manifesto --max-horas 24
```

The gate refuses to write posts when:

- the summary is malformed, stale, or has inconsistent probabilities or intervals (see [docs/contrato_resumo_publicacao.md](docs/contrato_resumo_publicacao.md));
- the manifest is missing (with `--exigir-manifesto`), or any recorded file changed after the run, for example a chart regenerated by another run.

## 3. Posting rules

- Post the generated text (`outputs/post_2turno_pt.md` / `_en.md`) with `outputs/simulacao_2turno.png` from the **same** run.
- Keep the disclaimer. State that the uncertainty parameters are priors calibrated on few elections (see [docs/calibracao_fase3.md](docs/calibracao_fase3.md)).
- When showing a bias scenario (`--vies`), present it as a scenario, never as the headline number.

## 4. After the election

```bash
python -m src.calibracao
```

Add the official result to `RESULTADOS_OFICIAIS` in `src/calibracao.py` with its TSE source. Add the final-week case to `casos_calibracao()`, rerun, and update `docs/calibracao_fase3.md`. Change a default only when the leave-one-out score supports it.
